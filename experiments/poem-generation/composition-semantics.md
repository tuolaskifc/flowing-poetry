# 3.3 整体场景语义与消费约定

2026-10-23。在 3.2 上新增 `scene`，旧协议与历史回答不改写。本版仍限 1–200 字节选、最多六个实体，不声称已经支持整首诗的分镜。

| 模型输出 | 本地消费者 | 可观察的作用 |
| --- | --- | --- |
| setting | 场景组织层 | 必要的环境依托与布局提案 |
| groups.role / pattern | 数量与语义绘画策略 | 主体突出、点景缩小、未明确计数的群落默认份数与分布 |
| groups.depth | 语义布局策略 | 相对远近、大小、透明度；不接受模型坐标 |
| supports | 场景组织与附着策略 | 水域、地面、山体依托及已提到船上的人影；推断不计入原文实体覆盖 |
| actions.state / pace / direction | 形态选择、绘画时钟与画布合成 | 支持的静止、飞鸟、水流、浮动、摇曳、飘落与烟的微动；未支持步态单列 |
| atmosphere / scene.atmosphere | 视觉气息策略 | 有限配色、远景淡化、动作节奏与空间疏密 |

所有解释带原文依据及 explicit/inferred 区分。明确数量、缺席、比喻边界优先于群落与构图推断。每个输出项要在计划中留下消费记录：已应用、未支持或未执行及原因。空数组不能冒充已理解。

本版动作是单一主导状态与本地观看动画；完整因果、多阶段先后、人物行走步态、16 类情感配色仍待实现。结构有效和字段被消费均不等于诗意或审美正确。

## 执行与回看

默认生成使用 3.3；显式 `mode:'scene'` 保留 3.2，旧回答不补造 scene。点击生成时通常调用一次 API，若最近成功记录的原句、提示、Schema、模型与规划版本指纹相同则复用；页面加载、选择、查看对照及交互调整均不请求模型。缓存不是全库永久缓存。

原始 `response.txt` 和 `analysis` 始终保留。只有校验失败全部属于引用未关联时，`source-context.mjs` 才可尝试将已有原文依据扩大到同句或相邻两句的连续片段。它不改变实体、数量、关系、在场或动作判断；必须重新完整通过检查，另存 `effectiveAnalysis`、`rawValidation` 与 `sourceContext`，强制标记待复核。更远跨句、伪造引文、字段错误和其他失败均不自动修正，不重试模型。同句共现不证明解读正确。

`single` 群落形式不是精确计数，未明数量不因此强制一只鸟。明确一舟、两鸟等数量仍优先。水田可作为水面依托，光源不当作落地实体；溪水经过石面只作局部空间承托，流体形变未支持。模型给出的不合理依托与工具不支持的动作进入缺口记录，不把日志中的字段存在当作视觉完成。
