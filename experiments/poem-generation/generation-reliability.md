# 生成稳定性与分级交付

2026-10-24 · 本地恢复策略 `generation-recovery-1.0`。不改变 expression-1.0 / abstract-1.0 的字段结构；主风景 3.3 原有处理保留。

用户遇到“解读没有通过检查，原始结果已保存；保留当前画面”。当前保存的 23 条融合记录中有 11 条失败，包含同两句的多次手动尝试，不能当作独立失败率。主要原因：比较关系误用了“在场主体动作”的约束，光照枚举包了 value/enum 对象，以及关系引用没有覆盖端点原词。

## 处理顺序

1. 保留模型原始文本和原始语义对象，先作严格检查。echo / contrast 可引用 role=reference、presence=unclear 的参照；这表示比较成立，不表示参照在场。确定过程、物理动作、场景分组与承托继续按在场约束检查。
2. 仅对已知的无歧义形状作整理：完整 JSON 外的一层 Markdown 代码围栏；scene.atmosphere.visibility / illumination 的单值 value 或 enum 包装。元数据必须一致，引文必须存在；不猜多值、矛盾 basis 或未知字段。
3. 当问题仅为引用未关联主体时，在原文同句或相邻两句内寻找覆盖已有引文和端点原词的最小范围。引用范围扩大不证明文学关联成立，结果标为待复核。不编引文，不改 mentions，不全诗兜底。
4. 可选联系、过程、场景分组、依托或动作有局部语义错误时，逐项验证并隔离；重复冲突的过程或分组全部暂不采用。缺少可选关系／过程组件时只提供空的本地视图，并说明模型没有返回该项，不冒充模型断言“没有关系”。
5. 主体、数量、原始输入、必需核心字段或未知绘图指令等有问题时继续失败。截断、网络失败、不完整 JSON 不猜补，也不自动重试。局部物理动作被隔离后，停止相应默认运动，避免被默认画法重新执行。

实体、原词、概念、数量、role、presence、modality 始终不因恢复而改写。结果中 `analysis` 是原回答；本地有效视图存为 `effectiveAnalysis`。`rawValidation`、`recovery.changes` 和 `recovery.omitted` 保留原失败、变化及未采用解释。

## 交付状态与体验

| delivery.status | 含义 | 画面 |
| --- | --- | --- |
| complete | 当前严格检查通过 | 正常绘制；仍不等于文学或审美正确 |
| adjusted | 无歧义格式／引用整理，或修正检查边界后重放 | 绘制并提示处理与复核 |
| partial | 只采用核验通过部分 | 明示有未采用的联系／动作，在歧义区列出原句范围 |
| failed | 核心内容不可用、服务失败或回答截断 | 保留旧画，明确它不是本次新画；按钮变为“重试本句” |

接口的 `validation` 描述有效视图，不能据此把 partial 统计为原始完整协议通过。原始情况必须看 `rawValidation`，交付状态看 `delivery`。

新增“回看最近生成”：从后端加载当前可验证的最近记录；原先因检查边界被拒绝的记录也可只读重放，旧文件不改。融合入口可用 `expression.html?latest=1`。最近记录的恢复不是新的模型回答。

缓存按同一诗句、模式、提示、Schema、模型、接口及策略指纹查找所有已有成功记录；A→B→A 可以直接复用 A，不只查最近的一句。局部结果仍保留 partial 标记。切换表达、种子、配色、铺展和回看不调用模型。
