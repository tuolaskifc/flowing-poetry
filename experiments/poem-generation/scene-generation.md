# 场景骨架与有限空间关系 · 3.2

更新：2026-10-21。当前生成器默认采用本版本；3.0 完整协议及 3.1 数量模块保持原文件，历史请求不改写。

## 这一轮改变了什么

1. **自然景物的映射**：`physical-mapping.mjs` 在匹配工具前区分自然景物与普通地名。寒江、山中、松下、河畔等即便被模型归为 place，也能进入对应画法；长安、松江等不因概念补充而自动变成江水或楼。复合词“江船”先识别船，不再误画成水。
2. **场景骨架**：新增本项目编写的 `landscape` 工具，区分山、岸、原野和小径。原树工具新增松意和叠墨树冠，组合器能组织树群；原水工具增加疏密水纹，由本地叠加水面色层，保留独立页的连续波纹模式。工具共 29 个；不把多个工具等同于完整意象覆盖。
3. **局部空间关系**：模型提供语义关系，本地 `scene-layout.mjs` 决定相对位置、层次和可用的图形效果。水与舟同场时可以先作水域定位，明确标为本地构图；模型关系与艺术安排分别记录。

树形与地形仍是基础写意试作，尚未获用户认可。水面定位不是物理承载，松树形态不是植物学鉴定，层山不表示原文有三座山。

## 语义边界

`scene-contract.mjs` 从数量协议扩展为 `schema_version="3.2"`，实体仍带 quantity，另增必填 `spatial` 数组（最多八项）。完整动作关系 `relations` 仍为空，不把有限空间试验称为完整协议成功。当前仍最多提取六个实体，长段诗句可能有覆盖损失。

| 字段 | 内容 |
| --- | --- |
| `type` | on、beside、behind、in_front_of、outside、among、reflects_on |
| `source`、`target` | 两个不同的已有实体 ID |
| `modality` | asserted、negated、possible、conditional、unclear |
| `basis` | explicit、inferred |
| `evidence` | 连续原文，关联两端主体；不能为画面补入原句没有的词 |

协议与校验器先落地，再实测模型。缺席、不确定与比喻参照仍不直接当作实景。未明确的数量、布局和方向不冒充原意；模型不返回坐标、画布参数、工具名或绘图代码。

当前实现：舟／鱼在水域的位置，前后层次、外侧／邻接的分组位置，月体与树隙的组织，以及**明确提出月影时**的水面淡影。未实现：水在石上流动、树影与复杂载体、真实遮挡光照、人物承载、完整动作与时间编排。仅同句出现不自动认定为明确关系，unsupported 关系保留在页面说明中。

## 固定二十句验收

入口：[本机场景对照页](http://127.0.0.1:4173/poem-flow/scene-review.html)。主网页导航已连接，打开不调用模型。

`scene-benchmarks.mjs` 为已有精选库编写固定的**手工语义测试样例**，不是模型回答。所有诗句、作者与篇名仍由原精选库提供；编辑目标不进入模型请求。基线使用 `1ef1b3d` 的规划、数量与词表，前后都用当前绘画工具重绘。

| 检查 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 样例列出的在场物象有基础画法 | 26/77 | 45/77 |
| 完全没有可画工具的样例 | 3/20 | 1/20 |

这些数字只计测试中列出的物象是否找到画法，既不是随机诗句成功率，也不是审美分数。瀑布样例仍为空，人物、白鹭、青苔、星空、光照等缺口保留。二十句均未标记“效果已认可”。

手工样例另验证“竹外两朵花，月影映水”：两朵花保持数量，竹与花分组错开；有无月影的 PNG 不相同。它是明确标记的自编测试句，不冒充古诗或真实 API 返回。
