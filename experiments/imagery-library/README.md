## 当前得到什么

- 五类各两个 OpenProcessing 候选，共 10 个，有原链接、可见许可、筛选理由与核实状态。
- 独立的本地试画页：花、树、水、云雾、鸟群，可统一调节风、笔触疏密、两组配色，支持暂停、换形态和逐张保存 PNG。

- **没有取得这批 OpenProcessing 原作的完整源码，没有完成这些原作的视觉审阅；本地试画不能当成候选作品的效果预览。**

## 打开试画页

直接用浏览器打开 [index.html](index.html) 即可。页面只读取已保存在本机的 p5.js 和实验脚本，无需联网或安装依赖；点击候选链接时才访问外部网站。

也可在项目根目录运行：

```powershell
node experiments/imagery-library/serve.mjs
```

再打开 [本地预览](http://127.0.0.1:4185)。预览服务只暴露本实验目录和指定的 p5.js 文件，未暴露项目根目录的 API 凭据。`?seed=42` 可以固定初始形态；时间推进仍会改变画面。

## 本地试验的设计边界

- **形态**：花与鸟目前是通用形态，尚未区分菊／梅／桃花或雁／燕／莺；树不是柳树等特定树种。
- **配色**：只从当前设计规范选用“清寂澄明”“温柔缱绻”两组颜色，是观看选项，不是自动情绪判断。未验证色彩面积比例。
- **疏密**：连续滑条只是试画参数，并未替用户确认三档或四档强度规范。鸟数固定 22，花数固定 7；改变线条、叶片细节或群体间距。
- **运动**：风只作为局部作用的试验输入；鸟仍有自主运动，不把风滑条当成全局情感或强度。
- **组合**：五个单元目前各自画在独立画布，尚未测试同场景的遮挡、承载、连接、层级与跨对象关系。
- **时间和逻辑**：本轮没有实现条件触发、否定、先后、完成范围，也没有将通用运动当成诗句事实。
- **性能**：本机小样的功能验证不代表安卓流畅度；五画布同时播放后仍需在目标设备实测。

## 验证与下一步

浏览器检查脚本 `verify.mjs` 使用本机 Edge 与本地预览；结果保存为 `verification.json`，画面保存为 `preview.png`。通过状态和具体覆盖范围以结果文件为准；这个记录不证明 OpenProcessing 原作运行成功。

本轮验证：直接打开本地 HTML 已通过；预览服务的页面、脚本和 p5.js 请求均返回 200，根目录凭据路径请求被拒绝（403）。本地 HTML 及 HTTP 两种路径可分别使用 `node experiments/imagery-library/verify.mjs` 和追加 `--http` 复核，HTTP 模式先运行预览服务。

看过本地截图后的初步审美判断：花、树可以继续细化；水目前是线性水纹；云雾仍像柔边色层，需要进一步组织体积与边缘；鸟群已具备群体运动，但还没有物种辨识与诗句角色。此判断仅针对本地试作，不是对社区候选的评价。

接下来最有价值的是对这五种本地画法做审美选择，并在可正常打开 OP 的浏览器中核实优先候选；完整源码、许可链和视觉都确认后，再把合适的算法纳入正式绘画库。不能把“已找到候选”直接提升为“已可复用”。
