# 流动诗：固定语义协议 3.0

状态：本次确定的后续实验与程序读取约定。Schema、提示词、校验器、说明样例和调用脚本已对齐；尚未用 API 验证模型对 3.0 的遵守程度，尚未接入绘画网页。

## 固定输出内容

LLM 每次只返回一个 JSON 对象。所有字段必须存在，不能自由增加字段、改名或返回代码。机器字段名使用英文，解释内容使用中文。

| 固定字段 | 内容 | 用途与边界 |
| --- | --- | --- |
| `schema_version` | 固定为 `3.0` | 识别协议版本，避免不同格式混读 |
| `poem` | 逐字保留输入 | 方便回查；本版接受 1–200 字的非空节选 |
| `reading` | 简短解读 | 供人审阅，不作为绘图指令执行 |
| `entities` | 最多六个主要意象 | 每个实体有唯一 id、原文称呼、规范含义、类别、场景角色、出现状态和证据 |
| `relations` | 最多六条联系 | 动作、比喻、位置和对照统一在此，不再平行生成 events 和 attributes |
| `atmosphere` | 感受倾向、强度、紧张感、开阔度，以及少量气息标签 | 固定维度供程序读取；标签供人阅读，不直接规定颜色、形状或速度 |
| `time` | 原文时间标记和必要说明 | 保留先后、未然、反复等提示，不替视觉程序决定结局或循环 |
| `uncertainties` | 最多三条待确认内容 | 不确定就指出，不以完整填表为目标 |

没有的列表写 `[]`；未明说的角色引用写 `null`；无法判断的枚举写 `unclear`。不把整句原样复制到每个说明里凑字段，也不返回置信度数字。

## 每个意象记录什么

固定字段：`id`、`mentions`、`concept`、`kind`、`role`、`presence`、`evidence`。

- `mentions` 列输入中的称呼，必须是连续原文。同一条船可以有“归舟”和“舟”两个称呼，只保留一个实体，避免画出两条船。真正同形异义的情况可保留多个实体，但需要审阅提醒。
- `concept` 是简短的含义，如“兵器”“秋风”，不是渲染器函数或某个图形库的编号。新词仍可解释，暂未有合适视觉表达时不强行画。
- `kind` 只用 object / organism / person / place / environment / abstract，分别为物体、生物、人物、地点、环境、抽象概念。
- `role=scene` 是场景主体，`role=reference` 是比喻参照。“戈鋋若罗星”中的罗星应是参照，不能因此自动创建实际星空。参照的 presence 固定为 unclear。
- `presence` 的 present / absent / unclear 只表示本句场景中的出现情况。“鸟不飞”否定的是飞行，不能仅因此将鸟设为缺席；“鸟飞绝”可以表达场景中没有飞鸟。
- 时间、距离等修饰不独立成为实体。“十月”进 time；“万里”支持对长风和整体开阔度的解释。

## 关系必须方向明确

每条固定为 `type`、`source`、`target`、`meaning`、`modality`、`basis`、`evidence`。引用只指向实体 id，不再引入另一套事件 id。

| type | source → target |
| --- | --- |
| `acts_on` | 影响者 → 受影响者，例如风 → 酒旗 |
| `moves` | 移动者 → null，没有明确接近/远离参照时使用 |
| `moves_toward` / `moves_away` | 移动者 → 明确接近/远离的参照 |
| `carries` | 承载者 → 被承载者，例如舟 → 人 |
| `grows_from` | 长出的事物 → 来源/承载体，例如白发 → 远客 |
| `disappears` / `changes` | 消失者/变化者 → null |
| `obscures` | 遮蔽者 → 被遮蔽者 |
| `located_in` | 所在之物 → 容纳它的地点、物体或人物 |
| `compared_to` | 被描写主体 → 比喻参照，例如兵器 → 罗星 |
| `contrasts_with` / `corresponds_with` | 对照/呼应双方，不暗示因果或先后 |
| `observes` | 观察者（可以未知） → 所见 |
| `other` | 暂不能归类的关系，保留 meaning 并进入审阅 |

需要双方的关系不能随意留空。比如“高楼位于 null”不能成立；反过来，原文没有明说观看者时，observes 的 source 可以为 null，不应因此补出具体人物。

以白发这一局部关系为例：

```json
{
  "type": "grows_from",
  "source": "i3",
  "target": "i4",
  "meaning": "白发从远客身上长出",
  "modality": "asserted",
  "basis": "explicit",
  "evidence": ["白发先从远客生"]
}
```

这里 i3、i4 分别是同一份回答 entities 中的白发、远客。这个片段只是协议说明，不是 API 的新返回。

## 不把假设、否定和推断变成事实

`modality` 固定使用：

- asserted：文字陈述发生或成立。
- negated：该动作/关系被否定。
- possible：可能、可以，尚未断言已经发生。
- conditional：条件假设，不能直接当成完成事件。
- unclear：暂不能判断，进入审阅。

`basis` 只用 explicit / inferred，区分文字直接支持与合理补出的联系。原文有“风、旗”可以合理推断吹动，但不等于原文明确写出了“招展”。

“人踪灭”可表示**消失已经发生**，应将 disappears 标为 asserted、实体标为 absent；不能又把“消失”取反一次。协议保留条件与未然信息，但“如果”的画面要不要始终趋近，仍是用户的艺术选择。

## 气息与时间

atmosphere 固定为 labels、valence、energy、tension、openness、evidence。valence 的 positive / neutral / negative / mixed / unclear 表示正向、中性、负向、混合或不明确的感受倾向，不是道德评价。后三个维度只接受 low / medium / high / unclear。labels 最多三个中文词，也可以为空；它们供人阅读，程序不依赖自由措辞去猜情绪。全部都是解释，不是测量值；不额外输出暖色、冷色、RGB、亮度或画面参数。

time 固定为 markers 和 note。每个 marker 只有 surface 与 meaning。保留“先”等提示，即使比较参照不清楚；note 说明缺少什么，不强制生成先后链。“归”主要表示返回方向，不能见到任何动词就当作时间词。

## 程序怎样接收

1. 按严格 JSON 读取，拒绝版本不符、字段缺失、额外字段和越界值。
2. 核对 mentions、evidence、时间标记是否来自输入，实体 id 是否唯一、引用是否存在。
3. 检查预设冲突，如比喻方向颠倒、比喻参照参与实际动作、缺席主体执行已发生的活动、消失的双重取反。
4. 对不确定性、other、重复称呼等给出审阅提醒。**valid=true 仅表示通过预设检查；review_required=false 也不是“诗意已经正确”。**
5. 检查失败就保留原回答和错误，不自动修复、不执行代码、不静默降级成随机画面。之后由本地视觉规则决定可用部分怎样表达，本次没有实现该绘图环节。

校验器不会因没见过的意象就编一个已知意象替代，也不能靠原文引用存在来证明解释正确。

## 本次实际完成与验证范围

- `schema.json`、`system-prompt.txt`：固定约定与共同提示词。
- `validate.mjs`：检查和可读展示，无网络请求，无代码执行。
- `examples.mjs`：九个人工说明样例，不是模型的新回答。前七项对应已保存的实验问题，另两项检查动作否定与假设。
- `offline-check.mjs`：核对说明样例并回查历史实验记录，输出 `样例与检查.md` 和 `offline-check.json`。没有改写历史记录，没有调用 API。
- 上级 `run.mjs` 默认使用 v3；v1/v2 只保留用于历史复现。`--prepare-only` 只准备待发送请求，不发出请求。

本次验证的是约定内部一致性、示例和拦截规则。模型对新格式的实际遵守率、文学解释、陌生输入和生成画面质量都仍待后续实测。

字段名、枚举含义、方向约定改变时另增版本，不能让绘画程序在同一版本下猜测不同解释。
