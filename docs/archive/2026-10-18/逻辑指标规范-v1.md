# 流动诗：逻辑指标规范 v1

记录日期：2026-10-18。

本版整理“逻辑”的名称、取值、作用对象与候选绘画方式，作为后续设计依据。逻辑状态与视觉表现必须分开记录；视觉表现尚未实现或验证。本文没有修改现行语义协议、调用模型或改动网页。

## 1. 逻辑负责什么

逻辑说明：某个意象在本句场景中是否出现，某个动作或关系是否成立，以及成立是否依赖条件。

“逻辑”作为项目内的统称，不表示要建立一套形式逻辑证明系统。这里的“成立”只针对诗句表达的场景，不是对现实世界或历史事件作真实性保证。

| 指标 | 要回答的问题 |
| --- | --- |
| 关系 | 谁与谁怎样联系？ |
| 逻辑 | 哪一项成立、被否定、尚属可能，或依赖什么条件？ |
| 时间 | 这种联系什么时候、按什么过程展开？ |

逻辑不负责选色。颜色来自情感配对表；强度负责图形紧密度与空间利用，不用强度代替逻辑状态。

## 2. 五种逻辑状态

状态名称沿用现行语义协议中 modality 的五种取值，避免仅为改称“逻辑”就新增一套同义状态。以下视觉方式是候选表达，不是已经确定的自动效果。

| 中文状态／取值 | 含义 | 候选绘画指导 | 不可擅自推得 |
| --- | --- | --- | --- |
| 成立 `asserted` | 文字陈述该动作或联系发生、存在或成立 | 允许相应结构、动作或结果状态实际出现 | 不保证动作完成，也不保证诗句来自真实事件 |
| 否定 `negated` | 文字否定某个动作或联系 | 保留缺口、受阻路径、未成立的连接等；具体取决于否定对象 | 不能一律删除主体，也不能一律改成排斥 |
| 可能 `possible` | 文字表达可能、可以或尚有选择 | 可试验候选位置、未闭合轮廓、尚未定形的连接 | 不直接当作已经发生，不擅自换算概率 |
| 条件 `conditional` | 动作或联系依赖某个条件 | 分开表示条件、条件满足情况及受影响部分，再决定变化或完成何时触发 | 不把所有假设都判为永不实现 |
| 不明确 `unclear` | 分析不足以确定这一项的状态 | 保留待确认，不把未确定的联系画成明确事实 | 不制造任意运动、轮廓或随机位置来冒充理解 |

可能是诗句表达的一种状态；不明确是解释尚有缺口。即使模型很确定诗句在表达“可能”，该事件也仍然只能标为 possible，不能因此改为 asserted。

## 3. 每项逻辑必须有作用对象

不能只给整句贴一个“否定”标签，然后让全画面消失。至少需要说明作用于什么。

| 作用对象 | 示例说明 | 应保留的信息 |
| --- | --- | --- |
| 主体的场景出现情况 | 本句场景中没有飞鸟 | 哪个主体缺席；这不表示该物种在现实世界不存在 |
| 动作 | 鸟不飞 | 鸟可以在场，飞行被否定 |
| 图形或语义关系 | 两端未能连接 | 两端可以保留，连接未成立；不自动转成相互排斥 |
| 完成或结果 | 正在靠近但没有抵达 | 接近可以继续，抵达或接触的结果受到限制 |
| 条件下的一组联系 | 条件成立后才发生后续行为 | 哪个条件控制哪些联系，而不是笼统影响整幅画 |

每项逻辑的范围应尽量精确。局部不确定不要求删除已经读清楚的其他意象或关系；如何使用已确定部分，需要在绘图选择中说明。

## 4. 设计记录要求

下表用于规范后续记录，不是本次新增的运行时 JSON 字段。对尚未明确的信息允许留空或记录 unknown，不以补全所有项为目标。

| 记录项 | 要求 |
| --- | --- |
| 逻辑状态 | 使用五种状态之一，不用情绪词或置信度代替 |
| 作用对象 | 指明是意象出现、动作、某条关系，还是完成状态 |
| 文字依据 | 保留连续原文片段，并说明否定词、可能词或条件结构的实际作用范围 |
| 解释依据 | 区分文字直接支持、语境推断、用户指定的艺术选择 |
| 条件内容 | 条件句中写清条件及受其影响的联系；内容未知时不补造 |
| 条件满足情况 | 仅在有依据或用户明确选择时记录满足／未满足；否则是未知，不能默认未满足 |
| 时间关联 | 保留尚未、一直、先后、完成等线索，不混同绝对否定 |
| 候选表现 | 记录使用空缺、受阻、未闭合、条件触发等哪一种方式，以及选择理由 |
| 待确认内容 | 记录范围歧义、条件缺失、语义冲突或尚未选定的视觉方案 |

“文字直接支持”与“推断”属于依据，不是额外的逻辑状态。关系强弱、画面强度、模型把握程度也不是逻辑成立程度。

## 5. 否定的具体处理

### 主体缺席与动作没发生

“鸟不飞”可以保留鸟的形态，让飞行没有发生；不能仅凭“不飞”就把鸟删掉。

“千山鸟飞绝，万径人踪灭”可以解释为飞鸟与人踪在场景中缺席，用空寂组织画面。这是对当前节选的解释，不是把每个“绝”“灭”都固定翻译成删除任何相邻物体。

### 消失发生，不是“消失被否定”

若文字表达消失已经发生，逻辑应为：消失成立，主体的结果状态为缺席。不能因为最终是缺席，就再次否定“消失”，造成两次取反。

在现行协议的说明例中，这对应 disappears 的 modality=asserted，与主体 presence=absent。若文字实际否定了消失，则须重新判断结果，不能照搬这一组合。

### 不连接与排斥

否定连接只表明连接没有成立。可以试验保留两端和缺口；只有文字或用户明确表达排斥时，才加入相遇偏转、绕开等排斥行为。

“尚未连接”还带有时间意义，不能自动处理成永远不连接。其后会不会完成，需要更多依据或艺术选择。

## 6. 可能的具体处理

possible 表示诗句中的开放状态，不是模型没有读懂。候选表达包括：

- 形态保留几个候选位置，但尚未固定到其中一个。
- 连接已有方向或轮廓，但尚未闭合。
- 保留准备发生的结构，同时避免把完成结果当成既成事实。

这些方案需要在实际画面中比较后选择，不要求同时出现。候选形态使用同一情感配色方案，不因“可能”另选颜色，也不以降低空间强度代替可能性。

原文没有概率时，不把 possible 固定成 50% 或随机触发频率。即使需要随机变体，也应记录为项目的生成选择，而不是诗句给出的概率。

## 7. 条件与用户最初的诗句

> 如果所有土地连在一起，走上一生只为拥抱你

这句的候选表达应分开记录：

| 层面 | 本项目已经讨论的选择 |
| --- | --- |
| 文字条件 | 所有土地连在一起；其具体作用范围仍需结合整句解释 |
| 意愿或目标 | 走向对方、拥抱对方，不直接断定拥抱已经发生 |
| 用户指定的艺术表达 | 画面始终趋近，不呈现完成的拥抱 |
| 关系组织 | 可试验土地的连接、两个主体的靠近 |
| 时间与完成限制 | 持续展现趋近，保留间隙，限制拥抱的完成状态 |

“始终未完成”来自用户对这幅作品的选择，不是“如果”一词必然要求的结局。条件尚未在场景中满足，也仍可以呈现愿望或假设层面的趋近；要标明这是愿望表达，不把它当作已实现的事实。

以后遇到其他条件句，条件满足情况默认保留未知；不能直接沿用这幅作品的未完成规则。

## 8. 与时间、关系和强度的接口

- 关系提供靠近、连接、承载等联系；逻辑决定它们是否成立、尚属可能或依赖条件。
- 时间负责展开、持续、延迟、反复与完成过程。逻辑只限制被指明的部分，不能替所有关系自动指定循环。
- 静态或否定飞行的主体仍可保留作品自己的细微动态；该动态是艺术选择，不应重新表现出被否定的飞行。
- 强度只调整紧密度、笔触和空间利用，不能用“强烈”把被否定的动作重新启动，也不能把“可能”自动降为低强度。
- “先”的参照不明时，时间指标保留提示并指出缺口；这不自动使整句全部变成 unclear。

静态诗句采用循环动画是播放设计，不证明原文描述了反复事件。任何默认播放方式都应与文字依据区分。

## 9. 与当前语义协议 3.0 的关系

| 当前字段或概念 | 对应内容 | 本版是否修改 |
| --- | --- | --- |
| relations[].modality | 动作或关系的五种逻辑状态 | 不修改字段名或枚举 |
| entities[].presence | 意象在场景中的出现情况 | 不与动作否定混成一个量 |
| relations[].basis | 文字直接支持还是推断 | 保持为依据，不并入逻辑状态 |
| time.markers / time.note | 时间线索及缺失的参照 | 保留与逻辑的联系，暂不改结构 |
| uncertainties | 模型或解释尚未确定的内容 | 不当成诗句本身的可能性 |

“逻辑”在本版是设计层的总称，**尚未新增名为 logic 的 API 顶层字段**。若之后确需把条件、范围等写入机器输出，应另行修订版本、校验器与提示词，不能在现有 3.0 中悄悄增加字段。

## 10. 验收与后续

后续测试应能明确区分：

1. 主体缺席、动作没发生、关系没成立、结果没完成。
2. 文本表达可能，与模型解释不明确。
3. 条件未知，与条件已经不满足。
4. 消失已经发生，与消失被否定。
5. 用户选择的永远趋近，与所有假设都永不实现。

结构冲突、引用断开或逻辑范围不明时应记录问题，不自动改写原文、伪造完成状态或用随机画面掩盖缺口。本文只整理规范，尚未进行上述 API 或画面验证。
