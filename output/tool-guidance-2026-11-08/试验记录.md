# 工具目录辅助选笔：第一轮试验

## 范围

将本地可用于共用绘画流程的 34 个工具的名称、能力边界交给模型（排除固定 22 只的旧鸟群工具），并要求逐主体返回工具、直接／近似／缺口、原文依据及画面预期。模型不提供可执行代码或坐标。输入是 `unfamiliar-2026-11-08` 中 n02–n06 已保存的五份模型解读；这是在同批解读之上的**第二次请求**，并不是输入诗句就一次完成，也不是独立的新诗泛化测试。目录由项目的 tool-manifest 及手工补充的能力边界构成，仍需逐项核对是否与正式共用渲染器完全一致。

第一版五次请求，3 次通过建议结构与安全边界检查，2 次未通过；返回用量共 16,303 token。原始结果保存在 n02.json 等。n03 对缺席主体选了工具且把 unavailable 和工具 ID 同时填入；n05 将 ID 写成“已有i1”等无效值。二者都保留，不当作合格建议。

修订版补充工具的实际形态名称，纠正提示中 ID 示例歧义，并对 n03、n04、n05 各再请求一次；3 份通过结构检查，返回用量共 11,178 token。`revision/` 中保存了本轮目录、提示和原回答。修订与首轮使用同一批既有语义，不是独立统计。

## 可取和局限

- n02：模型给竹、人物、莲、舟选到相应工具，并指出人物行走和船的完整行驶过程受限；它给出的左右、近远是构图建议，不是原文的明确空间关系。
- n03：修订版将缺席的荷及荷叶设为不画，识别残菊及菊枝的缺口；但它仍建议用盛开菊丛近似残菊，画面预期甚至说“可近似表现残菊”。这与目录明确的能力限制冲突，结构检查无法拦住文学和视觉错误。
- n04：第一版将渔火建议为舟并声称没有灯火；补充具体形态后，修订版选到 `landscape` 的灯火形态。它仍建议以鸟形表现乌啼、以草上霜线近似“霜满天”，均存在把听觉／寒意变成实物的风险，不能自动执行。
- n05：修订后主体 ID 规范，指出蛙缺画法；但它对工具默认份数的理解来自独立画笔目录，实际共用绘画流程可能按实例与数量规则重新组织，需更精确的运行上下文。
- n06：指出桅杆没有画法，并建议草、岸、舟；微风的本地参数和草的动作是否真正接通，不能仅凭建议断定。

模型的 `expected` 是基于目录的主观估计，不是实际画面或对审美的可靠评分。自动检查只验证结构、ID、原文引用及不把缺席／比喻／抽象主体交给实物画笔，无法验证工具是否与词义相符、选中的变体是否真实存在、内容是否足以构成诗意场景。暂不执行模型建议，也未修改现有生成入口或画面。要进入真实生图还需设计受控的工具变体、画笔能力和语义状态一致性校验，并用新诗做实际前后画面对照。
