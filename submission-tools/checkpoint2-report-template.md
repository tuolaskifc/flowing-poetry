姓名：刘阳　学号：2025011764　日期：2026-10-25

主要类别：软件开发；方向为中文诗句驱动的动态生成艺术。

## 一、目标与本阶段范围

我想做一个能把中文诗句变成动态图景的网页，先在电脑浏览器中使用，安卓留到后续。本阶段继续推进“流动诗”，没有更换选题。程序用模型解释诗句，由本地画笔与规则决定怎样画，不让运行时模型生成并执行绘图代码。

本周重点从“能识别几个意象并组合”推进到“组织一幅场景、尝试抽象表达、保留失败并提高可用下限”。完整的古诗理解、时间编排和审美还没有解决。

## 三、当前代码、环境与运行

实际检查环境：Windows、Node.js v24.18.0、Git 2.55.0.windows.2。p5.js 2.3.3 随仓库保存，主要运行路径使用 Node.js 内置模块，无需安装 npm 依赖。

| 位置 | 用途 |
| --- | --- |
| `poem-flow/` | 主界面、精选库、抽象／交融页面、对照图及浏览器验证材料 |
| `experiments/poem-generation/` | 模型请求、协议校验、失败记录、本地构图与绘画规则 |
| `experiments/imagery-library/drawing/` | 可复用画笔、来源与改编登记 |
| `experiments/poem-semantics/` | 早期语义实验、固定协议及说明样例 |
| `docs/` | 当前设计规范、参考资料与历史设计稿 |

在 `project/` 中运行：

```text
npm --prefix poem-flow start
```

然后打开 `http://127.0.0.1:4173/`。新句生成需要本地后端、外网和自己的模型配置。参照 `llm api.example.txt` 新建 `llm api.txt`；真实密钥不在提交包中。该配置是后端文件，不是上传到页面的内容。

无密钥时仍可查看 `poem-flow/rule-review.html`、`refinement-review.html`、`expanse-review.html` 等本地对照；通过 `/poem-flow/expression.html?latest=1` 回放已有融合结果。启动后的这些地址以本机服务为前缀。回放不等于重新请求模型。

检查命令为：

```text
npm --prefix poem-flow run check
npm --prefix poem-flow test
```

更详细的步骤见 `project/docs/checkpoint2-运行与复核.md`。`capture-*` 可能发出付费请求，不属于离线复核步骤。
